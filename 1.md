### 🎯 Project Context & Mission Brief

#### 1. What We Are Building
We are transforming this application into a high-octane, mobile-first **Arena Game Web Application** for the inauguration event of our **Incubation Lab**, where **200+ concurrent attendees/students** will participate live from their smartphones over local venue Wi-Fi.

#### 2. Key Product Requirements
- **Experience**: Fast, interactive game arena featuring real-time multiplayer/audience participation, live event scoreboard, and instant leaderboard sync.
- **Design System Fidelity**: Maintain the existing dark luxury monochrome design system (`ink`, `surface`, `chalk`, `ash`, and subtle `accent` glow using Tailwind CSS, *Plus Jakarta Sans* typography, and *Framer Motion*).
- **Mobile-First UX**: Zero-jank, touch-optimized, ultra-responsive UI tuned for diverse mobile devices and quick Wi-Fi connections.

#### 3. Why Self-Hosted Docker Supabase?
- **Zero Cloud Latency & Zero Egress Costs**: Running entirely on-premise on our local network avoids cloud bandwidth limits, cold starts, and internet dependency during the live ceremony.
- **200+ Concurrent User Resilience**: Backed by a lean Docker stack utilizing **PostgreSQL 17**, **Supavisor** (connection pooling to prevent connection exhaustion), and **Realtime (WebSockets)** for instantaneous leaderboard broadcasts.
- **Storage Policy**: All persistent database tables, player scores, and storage volumes are strictly mapped to the **D-Drive** (`D:\Arena\supabase\docker\volumes\`).

#### 4. Active Tech Stack
- **Frontend**: React 19, Vite, Tailwind CSS, Framer Motion, `@supabase/supabase-js`.
- **Backend / DB**: Self-hosted Docker Supabase (Postgres 17, GoTrue Auth, Realtime, Supavisor, Envoy Gateway at `http://localhost:8000` / LAN IP).
